# 07 — Security & reliability

A send must survive everything except losing the disk, and the app must never need unrestricted
root access.

## Reliability

| Mechanism | Implementation |
|---|---|
| **Background service** | The engine runs as a process separate from the window. On Linux it can install as a `systemd --user` service (`filebridge-service.service`, `Restart=on-failure`). Replaces `tmux`. Windows/macOS: launched at login (Tauri autostart / LaunchAgent) and kept alive by the tray. |
| **Automatic resume** | Network failures retry with growing waits — 30 s, 1 min, 2 min, … up to 15 min — **with no limit** while the user doesn't cancel. On startup, every non-terminal job resumes at its persisted stage; completed manifest entries are skipped. |
| **Block sleep** | While a send runs the system can't suspend: logind inhibitor (`systemd-inhibit` / D-Bus `Inhibit("sleep:idle")`) on Linux, `SetThreadExecutionState(ES_CONTINUOUS \| ES_SYSTEM_REQUIRED)` on Windows, `caffeinate -i` / `IOPMAssertionCreateWithName` on macOS. Released when the job leaves `Transferring`/`Verifying`/`Integrating`. |
| **Hidden partial files** | Files in progress use a temporary name (e.g. `.filebridge-<id>.partial`, or rclone's `--inplace=false` partial suffix) and only get the final name when complete. A scan mid-transfer never indexes truncated files. |
| **Manifest** | SHA-256 (or xxHash, faster) of each source file, with its destination name. Verification compares against the manifest and works even with corrected names. Algorithm is an [open decision](10-risks-and-open-decisions.md#open-decisions). |
| **Never delete the source** | There is no "move" mode. Freeing the source is a manual action, only available after a verification with **zero differences**. |

### Backoff schedule

```
attempt: 1    2     3     4     5      6+
wait:    30s  1m    2m    4m    8m     15m (cap, repeated forever)
```

Jitter ±10 %. Non-retryable errors (auth revoked, destination path gone, disk full) move the job
to `Failed` with an actionable message instead of retrying.

## Security

| Measure | Implementation |
|---|---|
| **Credentials and keys in the OS keyring** | `crates/secrets` wraps the `keyring` crate. SQLite stores only opaque references (`keyring:filebridge/<profile-id>/<kind>`). Never plain-text files. |
| **App-generated SSH key** | Ed25519 key generated by the app per profile; private key stored in the keyring, never written to disk unencrypted (passed to rclone via `--sftp-key-pem` over the local rc API, or a 0600 temp file deleted after the rclone process starts — decide in Phase 1). |
| **Dedicated user, not root** | The wizard suggests creating a dedicated user on the server (in the Nextcloud data group) instead of using root. |
| **Restricted key in direct mode** | `authorized_keys` line: `command="rrsync -wo <datadir>/<user>/files",restrict ssh-ed25519 AAAA…`. For SFTP use `ForceCommand internal-sftp` + `ChrootDirectory` in a `Match User` block as the alternative. |
| **Scoped `sudoers`** | `occ` runs through a `sudoers` rule limited to that command, e.g. `filebridge ALL=(www-data) NOPASSWD: /usr/bin/php /var/www/nextcloud/occ files\:scan *`. Today long `occ` commands run as `sudo -u www-data sh -c '<script>'` so they die with the SSH connection ([crate README](../crates/integration-nextcloud/README.md#direct-mode)); with this rule that watcher must move outside `sudo`. |
| **"Remove access" wizard** | Deletes the key on the server (`authorized_keys` line) and in the local keyring, then **tests that it can no longer log in**. Offered at the end of a migration. |
| **WebDAV with app passwords** | Nextcloud app passwords, revocable in Nextcloud itself; never the account password. |
| **No telemetry by default** | Nothing leaves the machine except the transfer itself. |
| **Logs** | Local logs include paths, **never credentials**. `tracing` fields for secrets use a `Redacted<T>` wrapper whose `Debug`/`Display` print `***`. |
| **rclone sidecar** | `rclone rcd` bound to `127.0.0.1` on a random port with `--rc-user`/`--rc-pass` generated per start; config passed in-memory, no `rclone.conf` with secrets on disk. |

## Threat notes

- The local machine is trusted; the server is trusted but access is minimised (least privilege).
- A stolen laptop exposes only what the OS keyring exposes when unlocked; app passwords and the
  generated key can be revoked server-side via "Remove access" from another machine or manually.
