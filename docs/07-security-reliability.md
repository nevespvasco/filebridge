# 07 — Security & reliability

A send must survive everything except losing the disk, and the app must never need unrestricted
root access.

## Reliability

| Mechanism | Implementation |
|---|---|
| **Background service** | The engine runs as a process separate from the window. On Linux it can install as a `systemd --user` service (`filebridge-service.service`, `Restart=on-failure`). Replaces `tmux`. The unit's process starts with the user manager's environment, not the session's, so it would miss the SSH agent that destinations without filebridge's own key sign in with: when `SSH_AUTH_SOCK` is a fixed per-user socket (under `$XDG_RUNTIME_DIR` or home) the unit sets it (`Environment="SSH_AUTH_SOCK=%t/…"`, the path only); when it moves at each login and the manager lacks it, installing warns, in the terminal and in the Settings confirmation. macOS: a LaunchAgent (`~/Library/LaunchAgents/app.filebridge.service.plist`, started again only after a failed exit; an agent socket under home goes into its `EnvironmentVariables`). Windows: a per-user Run key value that starts the app with `--start-engine`, which starts the service with no console window ([ADR 0028](adr/0028-login-start-on-every-desktop-os.md)). |
| **Automatic resume** | Network failures retry with growing waits — 30 s, 1 min, 2 min, … up to 15 min — **with no limit** while the user doesn't cancel. On startup, every non-terminal job resumes at its persisted stage; completed manifest entries are skipped. |
| **Block sleep** | While a send runs the system can't suspend: logind inhibitor (`systemd-inhibit` / D-Bus `Inhibit("sleep:idle")`) on Linux, `SetThreadExecutionState(ES_CONTINUOUS \| ES_SYSTEM_REQUIRED)` on Windows, `caffeinate -i` / `IOPMAssertionCreateWithName` on macOS. Released when the job leaves `Transferring`/`Verifying`/`Integrating`. |
| **Hidden partial files** | Files in progress use a temporary name (e.g. `.filebridge-<id>.partial`, or rclone's `--inplace=false` partial suffix) and only get the final name when complete. A scan mid-transfer never indexes truncated files. |
| **Manifest** | SHA-256 of each source file, with its destination name ([ADR 0017](adr/0017-sha256-for-the-manifest.md)). Verification compares against the manifest and works even with corrected names. |
| **Never delete the source** | There is no "move" mode. Freeing the source is a manual action, only available after a verification with **zero differences**. |

### Backoff schedule

```
attempt: 1    2     3     4     5      6+
wait:    30s  1m    2m    4m    8m     15m (cap, repeated forever)
```

Jitter ±10 %. Non-retryable errors (auth revoked, destination path gone) move the job to
`Failed` with an actionable message instead of retrying. A full destination (disk or quota)
**pauses** the job instead: the files that didn't fit wait, and Resume sends them once space is
freed ([ADR 0021](adr/0021-full-destination-pauses-the-job.md)). So does a source that can't be read (a disk
unplugged, a share dropped): its files wait, and Resume sends them once it is back
([ADR 0026](adr/0026-unreadable-source-pauses-the-job.md)).

## Security

| Measure | Implementation |
|---|---|
| **Credentials and keys in the OS keyring** | `crates/secrets` wraps the `keyring` crate. SQLite stores only opaque references (`keyring:filebridge/<profile-id>/<kind>`). Never plain-text files. Plugins read secrets only through the host's `SecretResolver` ([ADR 0004](adr/0004-os-keyring-secrets.md)). |
| **App-generated SSH key** | Ed25519 key generated by the app per profile on request; private key only in the keyring, passed to rclone in memory (`key_pem`) and decoded in memory for russh, never written to disk. See [ADR 0012](adr/0012-own-ssh-key-with-restrict.md). |
| **SSH host keys** | Every SSH connection (russh and rclone) checks the server's host key against `known_hosts` (default `$HOME/.ssh/known_hosts`, on a phone in the app's folder), offering only the key types on record for that host. An unknown server is shown in the wizard (or on Destinations, for a saved destination whose server is no longer known) with its key type and `SHA256:` fingerprint and added (appended, plain line, file 0600) only after the user confirms; a server whose key differs from the one on record is refused and never replaced from the app. See [ADR 0015](adr/0015-trust-unknown-host-key-in-the-app.md). |
| **Dedicated user, not root** | The wizard suggests creating a dedicated user on the server (in the Nextcloud data group) instead of using root. |
| **Restricted key** | `authorized_keys` line `restrict ssh-ed25519 AAAA… filebridge-<profile-id>` (no terminal, no forwarding). A forced `command=` (rrsync) is not used: rclone needs SFTP and direct mode runs `occ`, `chown` and `pct` ([ADR 0012](adr/0012-own-ssh-key-with-restrict.md)). |
| **Scoped `sudoers`** | `occ` runs through a `sudoers` rule limited to that command, e.g. `filebridge ALL=(www-data) NOPASSWD: /usr/bin/php /var/www/nextcloud/occ files\:scan *`. Today long `occ` commands run as `sudo -u www-data sh -c '<script>'` so they die with the SSH connection ([crate README](../crates/integration-nextcloud/README.md#direct-mode)); with this rule that watcher must move outside `sudo`. |
| **"Remove access"** | Deletes only filebridge's line on the server, **tries the old key and requires the server to refuse it** (taking it as a first factor before a password is not refusing it), and only then puts the profile back on its own key file, agent or password and deletes the key from the local keyring. If the server still accepts it, the profile keeps it. Offered on Destinations, at the end of a migration, and before deleting a destination that has the key. |
| **WebDAV with app passwords** | Nextcloud app passwords, revocable in Nextcloud itself; never the account password. |
| **No telemetry by default** | Nothing leaves the machine except the transfer itself. |
| **Logs** | Local logs include paths, **never credentials**. `tracing` fields for secrets use a `Redacted<T>` wrapper whose `Debug`/`Display` print `***`; IPC passwords are `Password`, same `Debug`. rclone's errors and stderr lines are scrubbed of secret parameters and of the exact secret values in use ([ADR 0004](adr/0004-os-keyring-secrets.md)). |
| **rclone sidecar** | `rclone rcd` bound to `127.0.0.1` on a random port with `--rc-user`/`--rc-pass` generated per start; config passed in-memory, no `rclone.conf` with secrets on disk. |

## Threat notes

- The local machine is trusted; the server is trusted but access is minimised (least privilege).
- The network is not trusted: the first connection to a server is only as safe as the user's
  fingerprint check (as with `ssh`); after that a changed host key stops every connection.
- A stolen laptop exposes only what the OS keyring exposes when unlocked; app passwords and the
  generated key can be revoked server-side via "Remove access" from another machine or manually.
